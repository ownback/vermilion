# PhxBringup.kext build history (PHX_KEXT_BUILD)

Moved verbatim from the `#define PHX_KEXT_BUILD` comment in PhxBringup.cpp on 2026-10-29 (build 78). Newest first.
For every new kext build: bump `PHX_KEXT_BUILD` and add its line at the top of this list (scripts/build/kext.sh
refuses an unbumped build). The host test suites named below (pipe2_test, pipe0_test, ...) belong to the development
tree and are not included here.

- 161 (not on the box yet; owner decision 2026-11-25: RX 7900 XTX only): b160 + a board gate. `PhxBringup::probe` and `start`, and `PhxFBSquatter::probe` and `start`, read three PCI config registers (vendor, device, revision; new PhxGpuId.h, host test tests/kext/gpu_id_test.cpp) and start only on 1002:744c revision 0xC8 (libdrm amdgpu.ids: C8 XTX; CC XT, CE GRE, CF 7900M and every other revision, and any other device, are refused). A refusal logs one line (`Vermilion: ... not an RX 7900 XTX ...`) and returns nil / false before any BAR is mapped, the bus-master or memory-enable bit is set, or `phxfb-squat` is taken from NVRAM, so a refused card keeps the firmware's display and IONDRV. The PCI "model" is always "AMD Radeon RX 7900 XTX" (the XT/GRE/7900M name switch of b125 is gone). No register access added; on the XTX the only change is three config reads at probe.
- 160 (not on the box yet; thread 02 part C): the parking of freed CPU-visible BOs that a CPU map still holds can no longer run out. b159 had 256 slots and leaked a BO's range past them for the rest of the boot. A process's maps go after its client frees its BOs, so every mapped BO parks at exit (Horizon: ~80 per run). There is now one slot per BO the pool can hold (pool size / 64 KiB, 10752 for [352, 1024) MiB, 258 KiB), allocated with the pool (no pool if that fails), kept packed. Parked BOs are reaped on every CPU-visible allocation and on every `debug.phxbo_vram_stat` read. stop() releases the parked BOs and frees the pool.
- 159 (EFI change 20, booted 2026-11-23 15:49 on the second try (the first stopped in OpenCore without a GOP, OWNER-TESTS watch #2); thread 02 part C): CPU-visible VRAM BOs inside the BAR0 window.
